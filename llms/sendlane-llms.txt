# Sendlane

> Email and SMS marketing platform for e-commerce. The Sendlane v2 REST API manages
> contacts, lists, segments, tags, custom fields, sender profiles, suppression lists,
> consent, campaign and SMS reporting, and ingests e-commerce behaviour events.

Generated by API Evangelist on 2026-08-13 from Sendlane's published OpenAPI and
documentation. Sendlane does not serve an llms.txt of its own — probed
https://www.sendlane.com/llms.txt (404) and https://sendlane.stoplight.io/llms.txt (404).

## Facts an agent needs first

- Base URL: `https://api.sendlane.com/v2`
- Auth: `Authorization: Bearer <SENDLANE_API_TOKEN>` — a static, account-scoped token
  generated from the API section of the Sendlane dashboard. No OAuth, no scopes, no
  expiry, no refresh.
- Also send `Accept: application/json`.
- Rate limit: 240 requests per minute per ACCOUNT, totalled across every key and
  integration. Exhaustion returns 429. No RateLimit-* headers are returned, so the
  remaining quota is not observable — track it client-side.
- Pagination: `limit` (default 100) and `page` (default 1). Responses carry
  `data`, `links{first,last,prev,next}` and `meta{current_page,from,last_page,path,per_page,to,total}`.
  Keep calling until `links.next` is null.
- Time filters: `from` and `to`, RFC 3339. `from` is REQUIRED whenever `to` is present.
  Percent-encode `+` as `%2b` in the query string.
- Errors: `{ "message": string, "errors": object|array }`. Validation errors key
  `errors` on the failing attribute; other errors return `errors` as an array. NOT
  RFC 9457.
- NO idempotency keys. Writes are not safe to blind-retry.
- The API can send real email and SMS. There is no test mode and no sandbox.

## Resource surface

- Contacts — `/contacts`, `/contacts/{contactId}`, `/contacts/search`,
  `/contacts/{contactId}/history`, `/contacts/unsubscribed`. 26 operations; the hub of
  the data model.
- Lists — `/lists`, `/lists/{listId}`, `/lists/{listId}/contacts`,
  `/lists/{listId}/unsubscribed`.
- Segments — `/segments`, `/segments/{segmentId}/contacts`. Read-only; segments belong
  to a list via `list_id`.
- Tags — `/tags`, `/tags/{tagId}`, `/tags/{tagId}/contacts`,
  `/contacts/{contactId}/tags`.
- Custom fields — `/custom-fields`, `/contacts/{contactId}/custom-fields`.
- Senders — `/senders`, `/senders/{senderId}`. Sender profiles are the verified
  identity a campaign sends from.
- Consent — `/contacts/{contactId}/email-consent`, `/contacts/{contactId}/sms-consent`,
  `/contacts/{contactId}/unsubscribe`. NOTE: the SMS consent endpoint must be enabled on
  the account by Sendlane support before it works.
- Suppression — `/suppression/emails`, `/suppression/domains`.
- Reporting — `/campaigns`, `/campaigns/{campaignId}/report`, `/sms-messages`,
  `/sms-messages/{messageId}/report`.
- Automations — `/automations/copy` (copies an automation into a second account named by
  the `Authorization-Destination` header).
- Back in stock — `/back-in-stock-contacts`.

## Events (inbound only)

Sendlane calls these "Custom Integration Webhooks", but the direction is INBOUND: you
POST events to Sendlane. Sendlane sends no outbound webhooks, so anything that happens
inside Sendlane must be polled.

`/tracking/added-to-cart`, `/tracking/back-in-stock`, `/tracking/category-added`,
`/tracking/checkout-started`, `/tracking/customer-added`, `/tracking/order-placed`,
`/tracking/product-added`, `/tracking/product-viewed`, `/tracking/event`.

Custom event types are registered under an integration:
`/integrations/custom`, `/integrations/custom/{integrationToken}/events`.

The same stream can be produced in the browser with the Beacon script:
`<script src="https://sendlane.com/scripts/pusher.js" async data-token="INTEGRATION_TOKEN"></script>`
(one instance per site only).

## What Sendlane does NOT publish

Stated plainly so an agent stops looking:

- No MCP server. `mcp.sendlane.com` is the app login, not an endpoint.
- No A2A agent card at `/.well-known/agent-card.json` or `/.well-known/agent.json`.
- No first-party SDK in any language registry. Integrators write raw HTTP.
- No GraphQL, no gRPC, no AsyncAPI.
- No `/.well-known/` documents of any kind, including security.txt.
- No sandbox or test mode. The only safe evaluation path is the 60-day free trial
  (100 contacts, 500 emails, no credit card).
- No API changelog. The product release notes stop at 2025-07-11.
- No published SLA and no deprecation policy.
